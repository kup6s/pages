    Installation#

    Via Helm (Recommended)#

    # Install from OCI registry
helm install pages oci://ghcr.io/kup6s/kup6s-pages --version 0.1.0

# Or with custom configuration
helm install pages oci://ghcr.io/kup6s/kup6s-pages \
  --set operator.pagesDomain=pages.example.com \
  --set operator.clusterIssuer=letsencrypt-prod \
  --set 'syncer.allowedHosts={github.com,gitlab.com}' \
  --set storage.storageClassName=longhorn \
  --set webhook.enabled=true \
  --set webhook.domain=webhook.pages.example.com

    Key Helm Values#

    ValueDefaultDescription
    operator.pagesDomainpages.kup6s.comBase domain for auto-generated URLs
    operator.clusterIssuerletsencrypt-prodcert-manager ClusterIssuer
    syncer.allowedHostsRequiredAllowed Git hosts (SSRF protection)
    storage.size10GiPVC size for sites
    storage.storageClassName(default)StorageClass (must support RWX)
    nginx.replicas2nginx replicas for HA
    webhook.enabledfalseEnable webhook IngressRoute
    webhook.domainwebhook.pages.kup6s.comWebhook endpoint domain

    See Helm Values Reference for all options.

    Verify Installation#

    # Check operator and syncer are running
kubectl get pods -n kup6s-pages

# Check CRD is registered
kubectl get crd staticsites.pages.kup6s.com

    NAME                                      READY   STATUS    RESTARTS   AGE

    Upgrading to the git CLI syncer (#153)#

    The syncer now runs the git command line with sparse, blobless clones instead of go-git. Read these notes before upgrading.

    Repository URLs must not redirect#

    The syncer does not follow HTTP redirects, because a redirect would carry credentials to another host. A StaticSite whose repository URL redirects (a renamed project, http to https, a server that redirects URLs without .git) goes to Synced=False with reason CloneFailed. It keeps serving its last content.

    Check every site before upgrading:

    kubectl get staticsites -A -o jsonpath='{range .items[*]}{.metadata.namespace}/{.metadata.name} {.spec.repo}{"\n"}{end}'

    Then, for each URL:

    curl -s -o /dev/null -w '%{http_code}\n' "<repo>/info/refs?service=git-upload-pack"

    A 3xx answer means spec.repo must be changed to the final URL. Private repositories may answer 401, which is fine.

    The first sync re-clones every site#

    Existing clones carry no marker, so the first sync after the upgrade replaces each one. Site directories with path: / become symlinks to the clone. Expect a burst of clones, and check the free space of the sites volume.

    Rolling back#

    The previous syncer cannot use the new layout. To roll back:

    1. Scale the syncer to 0.
    2. Delete /sites/.repos and the site symlinks on the volume.
    3. Roll back the chart.

    The old syncer clones every site again.
